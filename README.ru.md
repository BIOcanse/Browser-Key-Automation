# Browser Key Automation

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Deutsch](README.de.md) | [Français](README.fr.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-BR.md) | Русский

Browser Key Automation позволяет доверенному Agent или программе автоматизации управлять авторизованным локальным браузером Chromium через расширение Manifest V3 и API Key.

Расширение владеет аутентификацией Keys, разрешениями, ссылками браузера, занятиями и браузерными операциями. Небольшое сопутствующее App на Zig предоставляет только локальную маршрутизацию, назначенные App ссылки на browser Instance, сохранение файлов и явно объявленные нативные возможности.

> Статус разработки: текущая unpacked-сборка предназначена для Chrome/Chromium 138 и новее. Это не публикация в Chrome Web Store.

Отдельный ZIP для первой загрузки позволяет создать элемент Web Store, но его нельзя публиковать до синхронизации public key из Dashboard, ID расширения и Origin-фильтра локального App. См. [контракт поставки Chrome Web Store](docs/implementation/chrome-web-store-delivery.md).

## Возможности

- Создание, повторный показ, копирование, обновление, отключение и отзыв Root/Regular Keys на локальной странице управления. Сохранённый полный Key можно снова показать позднее.
- Получение списка вкладок и использование привязанных к runtime значений `TabRef`, `DocumentRef`, `NodeRef`, `TreeRef` и `ArtifactRef` вместо необработанных идентификаторов браузера.
- Просмотр кэшированного дерева операций страницы. Состояние раскрытия принадлежит каждому Key и сохраняется при уходе со страницы и возврате до обновления или замены документа.
- Поиск узлов без раскрытия дерева, одноразовые представления по глубине, диапазону соседей или поддереву, чтение ограниченного live DOM, описание узлов и выполнение DOM-операций.
- Выполнение JavaScript в явно выбранном world `USER_SCRIPT` или `MAIN`, когда в Chromium включён переключатель **Allow User Scripts**.
- Ожидание навигации, `interactive`, `complete`, условий DOM или текста.
- Сохранение текущей страницы в MHTML, получение проверенного снимка viewport, передача ограниченных Artifacts и открытие автономных HTML-демонстраций без локального HTTP-сервера.
- Отправка явного нативного левого клика Windows через `dom.click.real`. Его разрешение независимо от обычного `dom.click`.
- Занятие вкладки или глобальной области одним Key. Другой авторизованный Key должен явно освободить занятие, а затем получить его.

Command Registry является источником истины для точных методов, schemas, разрешений и ошибок. `system.describe` возвращает активную сборку и эффективные разрешения вызывающего Key.

## Архитектура

```text
Agent / автоматизация
        |
        | BKA_API_KEY + command
        v
Сопутствующее Zig App для Windows или Linux
        |
        | локальный loopback route + назначенный App InstanceRef
        v
MV3 offscreen transport
        |
        v
service worker расширения
        |
        +-- аутентификация Keys и разрешения
        +-- занятия и runtime-ссылки
        +-- вкладки, дерево страницы, DOM, JavaScript и Artifacts
        `-- необязательный запрос платформенной возможности
```

Расширение — единственный владелец бизнес-состояния. Сопутствующее App не хранит базу Keys и не принимает решений о разрешениях браузера. App назначает ссылку Instance каждому подключённому расширению; расширение не создаёт и не сохраняет собственный номер экземпляра.

Основной путь использует обычные разрешения расширения. CDP/DevTools может оставаться отдельной необязательной возможностью, но проект не может убрать собственное подтверждение отладки Chromium.

## Быстрый старт

### Требования

- Chrome или совместимый браузер Chromium версии 138 или новее
- Сопутствующее App для Windows x86_64 или Linux x86_64
- Node.js 20 или новее для включённой CLI
- Zig требуется только для сборки App из исходников

### 1. Соберите раздельные пакеты

```text
npm ci
npm run build:dev-package
```

Сборка создаёт три независимых архива:

- `out/browser-key-automation-extension-dev.zip`
- `out/browser-key-automation-local-app-windows-x86_64-dev.zip`
- `out/browser-key-automation-local-app-linux-x86_64-dev.zip`

Расширение и локальное App намеренно поставляются отдельно. В каждом архиве есть собственные `START-HERE.md` и `SHA256SUMS.txt`.

### 2. Загрузите расширение

1. Полностью распакуйте архив расширения.
2. Откройте `chrome://extensions`, включите режим разработчика и выберите **Загрузить распакованное расширение**.
3. Выберите распакованный каталог, в корне которого непосредственно находится `manifest.json`.
4. На странице сведений включите **Allow User Scripts**, затем перезагрузите расширение. Этот браузерный переключатель необходим только для `js.execute`; управление Keys, DOM и дерево страницы доступны и без него.
5. Откройте **Browser Key Automation** с панели инструментов. Для полностью доверенного управления создайте Root Key, для ограниченной области — Regular Key только с нужными разрешениями.

При первой установке открывается локальная страница настройки. Обновления и перезагрузки не открывают её повторно.

### 3. Запустите сопутствующее App

Распакуйте архив для своей платформы и оставьте relay запущенным:

```text
# Windows
.\browser-key-relay.exe

# Linux
chmod +x ./browser-key-relay
./browser-key-relay
```

Endpoint по умолчанию — `127.0.0.1:32189`. Если App недоступно, расширение повторяет попытки с настроенным номинальным интервалом 10 секунд до подключения. Не запускайте второе App, если фиксированный endpoint уже принадлежит совместимому экземпляру.

### 4. Подключите CLI

В распакованном каталоге локального App выполните:

```text
node client/browser-key-cli.mjs instances
```

Для этой команды Key не нужен. Ноль экземпляров означает, что расширение ещё не подключено. При нескольких экземплярах явно выберите актуальный `relayEpoch/instanceNumber`; никогда не пробуйте bearer Key на всех экземплярах.

Передавайте Key через переменную окружения, а не через argv:

```powershell
# PowerShell
$env:BKA_API_KEY = "bk1.<key-id>.<secret>"
node .\client\browser-key-cli.mjs call --method system.describe --schema-version 1 --params-json "{}"
```

```bash
# Bash
export BKA_API_KEY='bk1.<key-id>.<secret>'
node client/browser-key-cli.mjs call --method system.describe --schema-version 1 --params-json '{}'
```

CLI заново перечисляет экземпляры перед чтением Key. Если delivery указано как `unknown`, результат действительно неизвестен; не повторяйте автоматически команду с побочным эффектом.

## Типовые сценарии

- Исследование страницы: `tabs.list` → `page.tree.open` → `page.tree.find` или `page.tree.expand.v2` → `page.tree.view.get`
- Синхронизация: `page.wait`; без timeout используется 10 секунд, уже выполненное условие возвращается сразу.
- Сохранение страницы: `node client/browser-key-cli.mjs page-save --tab-ref <TabRef> --output ./page.mhtml`
- Снимок viewport: `node client/browser-key-cli.mjs page-shot --tab-ref <TabRef> --output ./page.png`
- Открытие демонстрации: `node client/browser-key-cli.mjs demo-open ./demo.html`
- Перед незнакомой командой проверьте `skills/browser-key-automation/references/commands.registry.json`. Включённый Agent skill содержит те же сгенерированные ссылки.

### Нативный клик `.real`

`dom.click.real` — явная возможность, независимая от `dom.click`. В Windows она просит Chromium активировать целевую вкладку и сфокусировать окно браузера, проверяет, что элемент по ссылке актуален, видим, включён и не перекрыт, после чего просит App отправить один нативный левый клик в соответствующее окно содержимого Chromium.

`{ "status": "input_sent" }` означает только принятие последовательности ввода, а не завершение сайтом нужного бизнес-действия. После этого наблюдайте страницу. Никогда автоматически не повторяйте неизвестный или неудачный нативный ввод. Linux App сейчас не объявляет `native.input.click.v1`, поэтому расширение отклоняет `.real` до подготовки страницы.

## Keys, разрешения и занятия

- Key — единственная внешняя идентичность. Марка Agent, процесс, учётная запись, socket и Instance App не являются дополнительными идентичностями авторизации.
- Root динамически получает все активные разрешения. Regular получает только явно выбранные разрешения.
- JavaScript, обычные DOM-операции, нативный ввод `.real`, сетевой доступ и будущие debugging backends — параллельные разрешения; выдача одного не выдаёт остальные скрытно.
- Команды одного Key сериализуются в текущем runtime расширения. Разные Keys имеют независимые lanes, но их эффекты на одной странице могут конкурировать.
- Занятие принадлежит Key. Скрытых takeover, force или replace нет: сначала release, затем acquire.
- Полный Key остаётся внутри расширения. Его могут получить доверенная страница управления и вызывающие стороны с отдельным разрешением `keys.create` или `keys.reveal`; обычные списки и диагностика его не содержат. CLI читает его только из `BKA_API_KEY` или явно выбранной переменной окружения.

Рассматривайте мощный Key как локальные учётные данные управления браузером и передавайте только доверенным Agents или автоматизациям. Техническое разрешение Key не заменяет разрешение пользователя на платежи, публикации, отправку сообщений, изменения учётной записи, удаление и другие значимые действия.

## Границы браузера и платформы

Chromium по-прежнему управляет host access, ограниченными страницами, доступом к file URLs, переключателем **Allow User Scripts**, включением расширения и подтверждением отладки DevTools. Root не обходит эти границы.

Apps для Windows и Linux предоставляют маршрутизацию и сохранение файлов. Windows дополнительно объявляет текущий backend нативного клика; Linux пока нет. Режим инкогнито и производные Chromium необходимо проверять с их собственными профилями и политиками.

## Разработка

| Команда | Назначение |
|---|---|
| `npm run generate` | Генерация проекций команд, UI, транспорта, capabilities и Freedom Points |
| `npm run check:extension` | Повторная генерация и проверка типов всех realms расширения |
| `npm run build` | Сборка расширения и Zig App для текущей платформы |
| `npm run test:unit` | Unit-тесты UI, Key, runtime, WebSocket и Zig |
| `npm run test:runtime` | Unit-тесты и изолированная интеграция relay/Chromium |
| `npm run build:dev-package` | Сборка расширения и Apps для обеих платформ |
| `npm run build:chrome-web-store:first-upload` | Сборка ZIP начальной идентичности только для создания элемента Web Store |
| `npm run test:dev-package-smoke` | Проверка структуры архивов, исполняемых файлов, хешей и ссылок skill |

Изолированные интеграционные тесты используют временные порты, профили и процессы relay. Они не должны быть направлены на личный профиль браузера или уже работающий личный Instance App.
