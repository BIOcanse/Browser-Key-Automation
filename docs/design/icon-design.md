# 图标设计

更新：2026-09-01。状态：用户已确认最终渲染，正式资产定稿；Chrome Web Store 继续暂停。

## 无损描述

一个图标同时表达“浏览器”和“Key 控制”。128 像素版本用于商店和扩展列表，16/32/48 像素版本用于工具栏；它们保持同一标志，但允许小尺寸删去无意义细节并做光学校正。最终资产以两份确定性矢量为源，生成四个 RGBA PNG，构建和测试只消费 PNG。

## 已确定约束

- 产品身份以 Key 为核心，浏览器是操作目标；不能只画通用机器人、鼠标或闪电。
- 不放文字、`BKA` 字母或语言相关内容，避免 16 像素不可读和本地化偏差。
- 使用管理页已有的 `#2563EB` 品牌蓝、白色和透明背景。不得使用渐变、发光、星芒、多彩高光或常见“AI 蓝紫”视觉。
- 128 PNG 的主要图形保持在中央 96×96 区域，四边各留 16 像素透明安全边缘。
- 16/32/48/128 都是独立导出的方形 RGBA PNG；小尺寸不得靠浏览器把 128 PNG 临时缩小。
- 白色“浏览器 + Key”作为一个不可拆分的视觉主体上下居中；不能只让蓝色底板居中。128 主稿与工具栏稿分别做光学校正，使主体顶部和底部留白近似相等。
- 图标不能改变扩展 ID、权限、命令、Key 数据或 App 门禁。只有用户明确恢复商店工作后才继续发布流程。

## 已裁定方向

以候选 B `Open Frame` 为基础，采用现代极简风：一个纯色蓝色圆角底、一个白色浏览器轮廓、一个白色钥匙。没有深色内窗，没有窗口三圆点，没有渐变、阴影、路径节点或装饰光效。

浏览器轮廓只用顶部与两侧表达页面容器，不画底边，并与钥匙圆环留出蓝色间隙；一条水平线表达浏览器顶栏。钥匙位于内容区，保留圆环、短轴和一个齿。图标只含两个可见颜色角色，任何细节都必须同时解释产品含义和小尺寸辨识。

首版白色主体的上、下留白分别约为 9.5 与 22 像素，视觉中心比蓝色底板中心高约 6 像素，表现为头重脚轻。修正只将完整白色主体下移，不改变浏览器与钥匙的相对比例、两者间隙、线宽或颜色。

文件结构：

```text
assets/brand/
├── browser-key-automation-icon.svg          # 128 商店/列表主稿
└── browser-key-automation-icon-toolbar.svg  # 16 基准工具栏稿，等比导出 16/32/48

apps/extension/static/icons/
├── icon-16.png
├── icon-32.png
├── icon-48.png
└── icon-128.png
```

## 裁定与落地顺序

1. 先分别完成 128 主稿和 16 基准工具栏稿，再导出四个 PNG；不把 128 主稿机械缩小到工具栏。
2. 在浅色、深色背景同时比较 128/48/32/16 的实际尺寸，不看放大后的单张图判断。
3. 验证尺寸、RGBA、透明边缘、两色限制、明暗背景对比、扩展工具栏实际显示和打包结果。
4. 用户已于 2026-09-01 确认最终渲染；这只确认图标，不自动恢复 Chrome Web Store identity、listing 素材或上传。

## 实现与验证

- `npm run render:icons` 是显式设计命令，不挂入普通构建；普通构建只消费已审阅并提交的 PNG。
- 渲染器拒绝渐变、滤镜、透明度效果、外部颜色引用和蓝白之外的可见颜色，再以隔离的无头 Chromium 导出精确尺寸 RGBA PNG。
- 两次独立导出得到逐文件一致的 SHA-256；`npm run test:icons` 验证两份 SVG 的两色约束，以及四档 PNG 的尺寸、RGBA、透明边缘、居中边界和实色占比。
- 完整 `npm run test:unit` 通过；源码 PNG、扩展构建目录和本地 Web Store 打包目录中的四档文件逐项 SHA-256 一致。该打包只发生在本机，没有上传或恢复商店流程。
- 最终对照图同时展示浅色、深色背景上的 128/48/32/16 实际尺寸，并单独放大 16 像素结构；放大图只用于看像素，不作为视觉比例判断依据。
